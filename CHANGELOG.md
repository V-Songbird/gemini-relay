# Changelog

All notable changes to **Gemini Relay** will be documented in this file.

## [1.3.0] - 2026-09-05

### Fixed
- **Large `@file` prompts on the `agy` backend**: the prompt now reaches `agy` on stdin (`--input-format stream-json`) instead of as one argv element, lifting the OS command-line cap (32,767 chars on Windows) that made `@package-lock.json` fail with `spawn ENAMETOOLONG`. Builds without `--input-format` keep `-p`.
- **`--print-timeout` raced the wrapper's own deadline at short timeouts**: it was `max(60, wrapper - 60)`, which at `GEMINI_MCP_TIMEOUT=1` gave agy exactly 60 s against a 60 s SIGKILL, so the wrapper killed agy before agy could report its own timeout with a usable message. Below a two-minute wrapper deadline there is no room to reserve a whole minute, so the derivation now halves instead: `wrapper > 120s ? wrapper - 60s : max(1s, wrapper / 2)`. At the default 45 minutes that is still `2640s`; at `GEMINI_MCP_TIMEOUT=0.5` it is `15s`. `AGY_PRINT_TIMEOUT` overrides the derivation outright.
- **agy errors surfaced verbatim**: a failed run's own message (`invalid model selection …`, quota, auth) now replaces `Command failed with exit code 1: Unknown error`.
- **Silently denied tool calls**: a run that exits successfully but reports `denied_actions` — a tool call the headless permission settings refused, with nobody there to approve it — now says so in a notice, instead of an edit appearing to have happened.
- **`@` tokens that name nothing**: `@param`, `@Injectable()`, `@types/node` and any other non-path token are left in the prompt exactly as written. Each used to be replaced by a `FILE NOT FOUND:` marker, as did every directory reference — including the documented `@.`.
- **Retirement notice on every single reply**: the "Gemini CLI was retired" notice was unguarded and prefixed every response from every tool for as long as the server ran. It now fires once per process, spent at the moment a caller actually receives it.
- **`ping` answered through a subprocess**: it spawned the `cmd.exe` `echo` builtin, so `ping "hello & world"` came back wrapped in the double quotes added for cmd safety. The echo is now in-process — nothing is spawned and nothing is timed, so `ping` proves the MCP transport is alive, not the CLI. The `args.message` fallback went with the subprocess: the zod schema declares only `prompt` and zod strips every other key, so `message` never arrived. With no argument the answer is `Pong!`.
- **Overlapping tool calls clobbered each other's progress**: keepalive state (interval, progress token, operation name, output preview) lived at module scope, so the first call to finish stopped the second call's notifications, mislabelled its completion message and leaked its output preview. Each call now owns its own state.
- **Prompt bodies written to the server log**, by both routes that carried them:
  - `Logger.commandExecution` echoed every argv element, dumping megabytes of inlined file text to stderr and from there into client logs — and a map keyed on start time pinned that argv for the life of the process on every path that never reaches `commandComplete` (timeouts, spawn errors). Only the argv *shape* is logged now (`--model`, then `<20 chars>` for anything that is not a flag), and no argv is retained between calls.
  - `Logger.toolInvocation` ran `JSON.stringify(args, null, 2)` on every `tools/call` dispatch, so the caller's raw `prompt` reached the log before `@` inlining had even started. It now logs the tool name and the *shape* of each argument that could carry a body: a **string** value becomes `<N chars>`, so the line reads `Tool ask-gemini(prompt=<4211 chars> model=<22 chars>)`. Non-string values — booleans, numbers, `addDirs`, an object `jsonSchema` — are still `JSON.stringify`'d in full, which is deliberate: none of them can hold a prompt, and their values are what a bug report needs.
  - `Logger.toolParsedArgs`, which interpolated the whole prompt into a `Parsed prompt: "…"` line, is deleted outright.
  With those three closed, no prompt body reaches the server log by any route.
- **Importing the server bound stdio**: `src/index.ts` connected the stdio transport on import. It now auto-starts only when it is the process entry point — `process.argv[1]` is realpath'd and compared case-insensitively against `import.meta.url` (the drive letter can differ in case on Windows), a directory `argv[1]` (`node .`, `node dist`, which node then resolves here through `package.json` `main`) counts as a direct launch because a directory is never an import, and an unknowable entry still starts, as before.
- **Windows install hint pointed at the wrong directory**: the "command not found" help now names `%LOCALAPPDATA%\agy\bin\agy.exe`, with the older `%LOCALAPPDATA%\Antigravity\` layout listed as a fallback.
- **`gemini-doctor` could hang or throw**: its probes used `execSync`. Every probe is now bounded (5 s per `--version`, 10 s for the account check) and caught.
- **`allowSlashCommands: true` could not actually reach a slash command**: agy answers a command in the CLI itself and refuses to under stdin delivery (`/usage is answered by the CLI itself and is unavailable with --input-format stream-json`), so the opt-out returned an error instead of the command's output. A `/`-prefixed prompt the caller opted into now travels as `-p <prompt>` on argv; a command is short, and this is the only delivery agy will answer it on.
- **Three tool schemas claimed a default model the code never sends**: `ask-gemini` and `brainstorm` advertised `gemini-3.8-flash-high` as their `model` default, and `gemini-models` printed it as the server's, but neither tool builds a `--model` argument when you leave `model` unset — agy answers on whatever model it is itself configured to use. Only `gemini-plan` pins that id, and `gemini-image` hardcodes it with no parameter to name. All four now say so.
- **Live e2e tests gated on the wrong binary**: `test/e2e/harness.ts` decided whether to skip by looking for the `gemini` CLI, but the server has defaulted to `agy` since the retirement date — so a machine with only `agy` skipped every live test it could have run, and one with only `gemini` ran tests that could not work. The harness and `scripts/doctor.mjs` preflight now both check the CLI of the backend the server will actually select.

### Added
- **`agent` on `ask-gemini`**: run a custom agent defined in an `agent.md` (`--agent <name>`) instead of the default one. Skipped on an `agy` build whose `--help` does not advertise the flag.
- **`allowSlashCommands` on `ask-gemini`** (default `false`): the relay now passes `--disable-slash-commands` — but only when the installed `agy` advertises it in `--help` — so a prompt starting with `/` reaches the model verbatim instead of being answered by agy's command layer. On a build that does not advertise the flag, or one whose `--help` probe produced nothing, it is not sent and a `/`-prefixed prompt is still expanded by agy's command layer. Set it to `true` to reach the free, zero-token commands (`/usage`, `/skills`, `/help`, `/agents`, `/model`, `/effort`, `/permissions`, `/hooks`, `/changelog`, `/config`, `/credits`) on purpose.
- **`skipPermissions` on `ask-gemini`** (default `false`): adds `--dangerously-skip-permissions`, on an `agy` build whose `--help` advertises it. Since agy 1.1.5 headless runs honour the persisted permission settings, so without it a tool call the settings disallow is refused with nobody there to approve it.
- **Conversation id reported back**: a plain-text `ask-gemini` reply names the conversation it created or continued, so a follow-up needs no digging in agy's private cache files. It is suppressed under `changeMode` and `jsonSchema`, whose output is parsed. `ask-gemini` is the only tool that reports one — `gemini-plan` and `brainstorm` read only the text and notices of their run, so no id reaches the caller there.
- **`size` on `gemini-image`** (`512`, `1K`, `2K`, `4K`), and the full aspect-ratio set the image tool accepts — `5:4`, `4:5`, `21:9`, `4:1`, `1:4`, `8:1`, `1:8` added to the original seven. Both travel in the prompt text, because `--model` selects the planner model and rejects image model ids.
- **Login and quota check in `gemini-doctor`**: a free, zero-token `agy -p "/usage" --output-format json` reports each quota bucket's remaining fraction and reset time. The verdict is decided by that payload, not by the exit code — agy exits 0 while signed out or exhausted.
- **Directory and glob `@` expansion**: `@src` (and `@.` for the whole project) inlines the text files beneath it, and `@src/**/*.ts` inlines a glob's matches (`*`, `**` and `?`; bounded at 200 characters and 6 stars, since `**` compiles to `.*` and an untrusted token could otherwise backtrack catastrophically).
- **Inline safety rails**: `node_modules`, `.git`, `dist` and the VitePress caches are skipped; secret-looking files (`.env*`, `.npmrc`, `.netrc`, `.git-credentials`, SSH keys, `*.pem` / `*.key` / `*.pfx` / `*.p12`) are skipped during directory and glob expansion; binaries are sniffed out; and the budgets are visible rather than silent — a file cut at the 256 KB per-file cap carries a `TRUNCATED:` marker in its own block, while files the 2 MB per-prompt budget pushed out, or that could not be read, are named in `OMITTED:` and `UNREADABLE:` footers. Every entry an expansion walks is re-canonicalized and re-jailed against the project root.
- **Capability probes**: one cached read of `agy --help` per process, scanned for every flag the backend can send — `--output-format json`, `--input-format stream-json`, `--model`, `--effort`, `--json-schema`, `--mode`, `--add-dir`, `--conversation`, `--print-timeout`, `--sandbox`, `--dangerously-skip-permissions`, `--disable-slash-commands` and `--agent` (plus `--continue`, kept for diagnostics now that nothing sends it) — so an older `agy` is never handed a flag that would fail the whole run. The probe is best-effort by design: `agy --help` is bounded at 4 s and any failure yields `NO_AGY_CAPABILITIES`.

### Changed
- **Node floor raised to `>=18.19.0`** (was `>=16.0.0`) in both `package.json` `engines` and the `package-lock.json` root entry that mirrors it, with a `"//engines"` note in `package.json` recording why: `node:test` needs 18 and the `tsx --import` loader in `scripts/run-tests.mjs` needs 18.19. CI runs 18.x, 20.x and 22.x. The optional SQLite transcript fallback additionally needs Node 22.5+, but it is a last-resort path that reports its own runtime error and does not raise the floor.
- **One capability-gating rule for every flag.** `--conversation` and `--sandbox` were pushed unconditionally, so an `agy` build without them failed the whole run on an unknown flag. `buildAgyArgs(opts, caps)` now takes a **required** capability set — no caller can opt out of the probe — and applies the same test to every flag it builds: send it only when the installed `agy` advertised it in `--help`. `--model`, `--effort`, `--json-schema`, `--mode`, `--add-dir`, `--conversation`, `--sandbox`, `--agent`, `--disable-slash-commands` and `--dangerously-skip-permissions` are all gated that way, and `run()` decides `--input-format` / `--output-format` / `--print-timeout` by the same rule. The earlier permissive idiom (`(!caps || caps.X)`), which also sent a flag when the probe produced nothing, is gone: it never fired at runtime, because `run()` always awaits `probeAgyCapabilities()` and a missing, unparseable or timed-out `agy --help` resolves to `NO_AGY_CAPABILITIES`, in which every capability is `false`. When the probe finds nothing, no flags at all are sent and the run falls back to agy's own defaults, which is cheaper than risking a non-zero exit on an unknown flag.
- **Two tool descriptions corrected**, since `tools/list` is what an agent reads before it picks a tool and both were making claims nothing in the repo supports:
  - `ask-gemini` dropped "with massive context window" and the Gemini-only model list, and now names the catalogue the Antigravity CLI actually offers — Gemini 3.8 / 3.7 / 3.6 Flash and 3.1 Pro, plus the Claude and GPT-OSS models — and the `@path` file-reference behaviour.
  - `gemini-image` no longer says "Google Gemini & Imagen"; it names the Antigravity CLI's image generation tool, and mentions output size alongside aspect ratio.
- **Parameter descriptions on `ask-gemini` now state their exceptions**, because the schema text is what an agent reads before it calls:
  - `conversationId` — a plain-text reply reports the id it created or continued; a `jsonSchema` or `changeMode` reply does not, because its body is parsed.
  - `includeUsage` — ignored when `jsonSchema` is set, so the body stays valid JSON.
  - `sandbox` — the `agy` backend forwards it but does not isolate tool execution in headless runs, and says so in a notice; the legacy `gemini` backend does isolate.
  - `chunkIndex` — with `chunkCacheKey` it reads the cached chunk; alone it selects which chunk of a *fresh* `changeMode` result to return, so it is not inert without a key.
  - `chunkCacheKey` — the 8-hex-character key a multi-chunk reply reported.
- **Prompt delivery and reply parsing**: where `--input-format stream-json` exists the prompt is written to stdin as one NDJSON message and the answer is read from the final `result` event, which also carries the status, error, conversation id and denied actions. Builds without the flag keep `-p <prompt>`.
- **Session resume is explicit**: only `conversationId` (`--conversation <id>`) resumes a thread.

### Removed
- **The `contribute` npm script**, which pointed at a `src/contribute.ts` that does not exist.
- **Global `--continue` resume**, along with the `resume` and `sessionId` backend options: `--continue` resumes the most recent conversation anywhere on the machine, which no caller can reason about.
- **`src/scripts/deploy-wiki.sh`**.

## [1.2.0] - 2026-09-03

### Initial Modern Release
- **Gemini 3.8 Flash & Gemini 3.1 Pro Support**: Native integration with Google's latest model family (`gemini-3.8-flash-high`, `gemini-3.8-flash-medium`, `gemini-3.8-flash-low`, `gemini-3.1-pro-high`, `gemini-3.1-pro-low`).
- **Antigravity CLI (`agy`) Primary Engine**: Full headless execution via Google's modern Antigravity CLI with automatic model selection, JSON streaming, and session continuity.
- **Multimodal Image Generation (`gemini-image`)**: Generate high-definition visual assets directly from prompts with aspect ratio control and automatic project export.
- **Architectural Planning (`gemini-plan`)**: Dedicated non-destructive planning tool utilizing Gemini's plan mode (`--mode plan`) and maximum reasoning effort for phased implementation blueprints.
- **Reasoning Effort Control**: Fine-tune thinking token depth with `effort: "low" | "medium" | "high"` across queries and ideation tasks.
- **Guaranteed Structured Output (`jsonSchema`)**: Enforce valid, machine-readable JSON matching any user-provided schema for automated agent workflows.
- **Model Discovery (`gemini-models`)**: Real-time capability matrix and model introspection tool.
- **Environment Diagnostics (`gemini-doctor`)**: Health-check tool verifying CLI binaries, versions, active backend and execution environment. (Login and quota verification arrived later — see Unreleased.)
- **Structured Multi-File Refactoring (`changeMode`)**: Edits are *requested* as a `**FILE: path:line**` header over a fenced block holding an `OLD:` section and a `NEW:` section, and *returned* in the parsed form — a `[CHANGEMODE OUTPUT …]` header, then one `### Edit N: <file>` section per edit with a "Replace this exact text:" block and a "With this text:" block — with paginated chunk caching for massive codebases.
- **Cross-Platform Process Hardening**: Direct binary execution on Windows (`shell: false`) bypassing `cmd.exe` multiline prompt corruption. (The command-line length ceiling was lifted later, by stdin delivery — see Unreleased.)
- **Project Jail Security Guard**: Strict root confinement for `@file` and `@dir` references preventing path traversal attacks.
